A helper that keeps working after you close the tab

Most chatbots only think while you're talking to them. This one is woken up by things happening: an email arrives, an alarm rings, a person says yes. Between jobs it sleeps and costs nothing.

It's a working copy of Anthropic's Building always-on agents, running on Cloudflare. Drop something in its inbox and watch its desk below. Read the code on GitHub.

Inbox tray

Every letter gets a ticket and waits its turn. If the same letter shows up twice, it gets stamped and ignored, so nothing is done twice.

    How it's built

    Think's submitMessages() with an idempotency key made from the source and the event id. Tickets live in the Durable Object's SQLite and run one at a time, in order.

    The helper

    Asleep

    It picks up one ticket, reads its notebook, decides what to do, uses its tools, and goes back to sleep. Nobody has to keep a window open.

    How it's built

    One Durable Object per visitor, running Cloudflare's Think agent harness. Claude Haiku 5.5 does the thinking, set to low effort with at most 4 tool rounds per job to keep it cheap.

    Outbox tray

    The helper never shouts out the window. Anything it wants to say goes in this tray, and a mail carrier delivers each piece exactly once.

      How it's built

      An app_outbox table keyed by idempotency key, so a redone job can't send twice. A dispatcher on the Durable Object alarm delivers each row (log or webhook) and retries failures.

      Needs your signature

      Some jobs are too risky to do alone, like giving money back. The helper fills in the form, puts it here and goes to sleep. When you sign, it wakes up and finishes.

        How it's built

        A Think action with kind: "durable-pause". The run ends; the paused action is stored. approveExecution() runs it and continues the conversation, hours or days later.

        Notebook

        The helper forgets everything when it sleeps, so it writes things down and reads the notebook every time it wakes.

        How it's built

        Think Sessions store the conversation in SQLite, plus a memory block the model can rewrite for standing rules.

        Alarm clocks

        Ask it to check back later and it sets an alarm. When the alarm rings, it's just another letter in the inbox.

        How it's built

        The agent's schedule(), which sits on the Durable Object alarm. When it fires it calls followUp(), which drops a new event in the inbox.

        What just happened

        The same story in words, as the desk changes.

          A long chore with a pause in the middle

          Some jobs have several steps and a wait where a person has to say OK, maybe days later. The helper ticks off a checklist as it goes, and finds each tick by the step's name.

          That's why the rule for updating a helper is: add new steps, never rename old ones. Change the instructions while it's paused and it skips every step it already ticked. Rename a step and it can't find the tick, so it does that step again.

          Update that adds a step Gather changes and Write notes were already ticked, so they're skipped. The new step, Tell the team, runs, then Publish. Nothing is done twice.
          Update that renames a step Write notes was renamed to Write release notes. The helper can't find a tick for the new name, so it writes the notes again and pays for a second AI call.
          How it's built

          A Cloudflare Workflow (ThinkWorkflow). Step names are cache keys: step.do("draft-notes") returns its saved result on resume. The pause is waitForApproval(); the instance sleeps without using compute. Both runs above are real results from the repo's demo script.
